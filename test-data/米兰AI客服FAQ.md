# 米兰AI 客服知识库

## 一、关于米兰AI（项目概览）

### 米兰AI 能做什么？

米兰AI 是一个基于 Spring AI 构建的全栈 AI 应用。使用它，你可以获得：智能客服（RAG 知识库问答）、智能对话（多轮聊天）、知识库文件管理（上传 / 分页查询 / 编辑备注 / 删除）、向量检索增强、联网搜索、会话历史管理、SSE 流式打字机输出，以及推理过程透出。

---

### 米兰AI 包含哪些功能模块？

一共两大模块、十一个接口：

- **智能客服**（`/customer-service`）：`/md/upload` 上传知识库、`/md/list` 分页查询、`/md/update` 改备注、`/md/delete` 删除、`/chat/completion` 客服问答
- **智能对话**（`/chat`）：`/new` 新建会话、`/completion` 对话、`/list` 会话列表、`/message/list` 历史消息、`/summary/rename` 重命名、`/delete` 删除会话

---

### 米兰AI 是用什么技术栈实现的？

**后端**：Spring Boot 4.1.0、JDK 21、Spring AI 2.0.1、PostgreSQL + pgvector、MyBatis-Plus 3.5.16、HikariCP、p6spy、Log4j2、OkHttp、Jsoup、Hutool、Guava。

**前端**：Vue 3.5、Vite 6、Ant Design Vue 4.2、TailwindCSS 4、Pinia、Axios、Vue Router、`@microsoft/fetch-event-source`。

**模型服务**：阿里云百炼（OpenAI 兼容接口），对话模型和向量化模型可分别配置。

---

### 怎么获取和部署米兰AI？

前置条件是 JDK 21、Maven 3.9+、Node.js 20+、PostgreSQL 15+（装 pgvector 扩展）。

后端：建库并执行 `CREATE EXTENSION IF NOT EXISTS vector;`，把密钥写进 `application-secret.yml`，配好数据库连接，然后 `mvn spring-boot:run`，默认端口 8080。

前端：`npm install` 然后 `npm run dev`，默认端口 5173。

---

### 部署一套米兰AI 大概要花多少钱？

软件本身没有授权费用，全部开源。主要成本是**模型 API 的按量计费**：

- 数据库：PostgreSQL 本地自建，0 元
- 向量检索：pgvector 是 PostgreSQL 的扩展，0 元
- 模型调用：阿里云百炼按 token 计费，日常调试一个月通常几块钱
- 服务器：本地跑就 0 元；上云的话最低配 1 核 2G 就够

---

### 知识库支持上传哪些文件格式？

目前只支持 **Markdown（.md）** 格式，上传时会校验扩展名，其他格式会被直接拒绝。

文档上传后会按标题层级和分割线自动切分，每个片段都会带上标题、分类、关联文件 ID 和原始文件名等元数据。

---

### 上传一个文件后，多久能检索到？

上传接口会先落盘、写数据库记录，然后**立刻返回**，向量化是异步执行的。

处理耗时取决于文档长度和向量化模型的响应速度，一般几秒到几十秒。状态会从「待处理」变成「向量化中」，最后变成「已完成」。

---

### 这个项目的分页查询有什么限制？

每页最多 **100 条**，超过会被参数校验拦下；每页默认 10 条。

分页支持按文件名模糊查询和按创建时间范围筛选。注意筛选条件变化后要回到第 1 页，否则可能请求到不存在的页码导致表格空白。

---

### 知识库文件的备注有什么限制？

长度上限是 **500 个字符**，数据库、后端校验、前端输入框三处都是 500。

允许为空，在编辑框里留空提交就能清空原有备注，不需要逐字删除。超出 500 字符时输入框会直接拦住打不进去。

---

### 米兰AI 适合什么人使用？

适合正在学习 Java、想通过完整项目实战提升能力的同学；需要高质量项目写进简历的 Java 开发者；以及想入门 AI 应用开发（Spring AI 方向）的后端工程师。

---

### 项目可以二次开发和商用吗？

可以。代码托管在 GitHub，可以自由 fork 和修改用于自己的业务场景。

需要注意的是：二次开发时请把 `application-secret.yml` 里的模型密钥替换成你自己的，不要沿用仓库里的默认值。

---

## 二、常见问题与排障

### 启动后端时提示端口被占用怎么办？

先换端口试试：启动时加 `--server.port=8090`。

还有一个容易踩的坑：某些终端环境会注入 `SERVER_PORT` 之类的环境变量，Spring Boot 的松散绑定会把它解读成 `server.port`，优先级高于配置文件，导致应用去监听一个你根本没配过的端口。显式传 `--server.port=8080` 可以覆盖掉。

---

### 文件一直卡在「向量化中」怎么办？

多半是服务在向量化途中被中断或重启了，属于僵死记录，它不会自动恢复。

此时普通删除会被拒绝，需要在删除确认框里选择**强制删除**；接口层面对应传 `force: true`。强制删除会跳过状态检查，同时清理数据库记录、对应的向量和本地磁盘文件。

---

### 客服回答不准确，怎么排查？

回答时系统只取最相似的 **3 条**片段（`topK=3`）拼进提示词，所以排查方向有四个：

一是知识点根本没被切出来——检查 Markdown 的标题和分割线是不是被转义了（从网页复制来的内容常带 `\*\*`、`\---`）。

二是切分粒度不合适——一个片段塞了太多主题会让向量"平均化"。建议一个二级标题只讲一件事。

三是只取 3 条——答案分散在 4 个以上片段时必然遗漏，可以在代码里调大 `topK`。

四是提问方式和文档表述差太远——向量检索看语义相似度，口语化提问和书面化文档之间有距离，可以在文档里补充同义说法。

---

### 更换向量化模型需要注意什么？

向量化模型一换，输出维度往往也跟着变，而已经入库的旧向量是按旧维度算出来的，两者无法混用。当前项目用的是 **1024 维**。

正确做法：同时改 `spring.ai.openai.embedding.dimensions` 和 `spring.ai.vectorstore.pgvector.dimensions`，重建 `t_vector_store` 表（或改 `embedding` 列维度），最后把所有知识库文件重新上传一遍。只改配置不重建表，写入时会直接报维度不匹配。

---

### 联网搜索用不了怎么办？

联网搜索依赖 SearXNG，在 `application-dev.yml` 里配置 `searxng.url`（默认 `http://localhost:8888/search`）和 `searxng.count`（默认 10）。

SearXNG 是可选依赖，**没启动也不会影响知识库问答和基础对话**，只是联网相关能力会降级。

---

### 两个流式接口的返回格式有什么不同？

两个接口都用 SSE，前端通过 `@microsoft/fetch-event-source` 接收，但**返回体格式不同，不能照抄**：

客服端 `/customer-service/chat/completion` 返回**纯文本**，直接追加即可。

对话端 `/chat/completion` 返回 **JSON**，形如 `{"v":"...","reasoning":"..."}`，`v` 是正文、`reasoning` 是思考过程，需要 `JSON.parse` 后分别渲染。

---

### 密钥应该放在哪里？

放在 `src/main/resources/application-secret.yml`，**不要**写进 `application-dev.yml`。推荐写成 `${DASHSCOPE_API_KEY:你的密钥}` 这种形式，部署时用环境变量注入，本地开发回退到默认值。

`.gitignore` 已经忽略了这个文件，但提交前仍建议用 `git status` 复核一遍。万一推上去了，请立刻去模型服务商控制台重新生成密钥。

---

### 文档里找不到我要的答案怎么办？

可以到 GitHub 仓库 `qiufengmm/milan-ai-robot` 提交 Issue 描述你遇到的问题，附上报错日志和环境信息会更快得到回复。

也可以在问答前先确认：你要查的内容是不是已经上传进知识库了——系统只能基于已上传的文档作答，超出范围的问题会统一回复"暂未查到相关资料"。
