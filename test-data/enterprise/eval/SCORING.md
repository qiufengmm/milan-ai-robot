# 评测判分说明

对每一用例分别判断三项，不得用“检索到了某个块”替代答案正确性：

| 字段 | 通过条件 |
| --- | --- |
| `retrievalCorrect` | 来源文件/版本覆盖该题所需事实；权限/澄清类按用例验证实际范围或行为 |
| `answerCorrect` | 回答覆盖 `expected` 的必答事实、条件和下一步，且没有相反/臆造承诺 |
| `evidenceSupported` | 答案中的可核查事实都能由返回来源支持；无依据题须明确表示资料不足 |

判分范围：`expected` 只列本轮问题实际询问的必答事实。不得把同一知识块里未被询问的相关事实追加为必答项；回答准确覆盖问题时，即使没有顺带复述这些相关事实，仍可判答案正确。对信息不足的提问，评估澄清是否询问了当前最关键的一项；允许分轮补问，不要求在首轮一次列出所有可能条件。

权限用例另按 HTTP 状态和响应是否泄露数据判定；配置缺失时记为 `CONFIG_REQUIRED`，不得当作通过。版本用例记录实际当前文件ID与版本号，确认草稿/历史版不会进入新一轮检索。

统计时同时列出有效回答数、空回答/错误数、自动状态数、需配置的用例数、多轮请求总数、TLS 握手原始失败与单次重试结果。平均与中位耗时只统计成功 `done` 的请求，说明统计口径。对每题登记实际模型、温度、库 ID、发布文件 ID/版本及评测时间。

只对明确的 TLS 握手失败且没有得到答案重试一次。先前失败要保留为第一次尝试记录。HTTP 401/403、429/额度耗尽、模型错误、无资料拒答和已有正常答案都不重试。

若修订判分口径，保留原始回答、来源和运行状态，只更新 `expected` 与人工判分字段，并在评测报告说明影响范围；此类重评分不得写成代码修复后的新一轮评测结果。
