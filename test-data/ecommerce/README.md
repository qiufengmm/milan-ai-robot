# 米兰数码商城 · 电商客服知识库（演示数据）

本目录是「米兰 AI 智能对话平台」智能客服模块的**电商场景知识库**，用于把通用的客服演示改造成「基于私有知识库的电商商品咨询与售后问答系统」。

## 1. 免责与边界

- **米兰数码商城是虚构店铺**。文中商品型号、参数、价格、时效、政策条款、客服邮箱均为**演示数据**，不对应任何真实商家；`support@milan-digital.example.com` 使用的是保留域名 `example.com`，不会真实收信。
- 知识库只放商品资料、服务规则与操作说明，不含真实个人信息、实际订单号或实时订单状态。
- 项目保留 Java / Spring Boot / Spring AI 单体架构及现有 SSE 对话协议。第 14–15 章在其上补充分片上传校验、多知识库隔离、Elasticsearch BM25、RRF、Rerank 与索引同步任务；本目录保存商城演示语料、评测及简历材料。

## 3. 与现有解析器的适配约定

这些约定是为了让知识块**不被切碎、不丢字**，改动知识库时请遵守：

1. **用 `---` 明确知识块边界**。`MarkdownReader` 配置了 `withHorizontalRuleCreateDocument(true)`，遇到水平线会结束当前文档；读取器也可能在标题等节点切分，不能依赖跨段上下文。
2. **避免把规则写成引用块 `>`**。`withIncludeBlockquote(false)` 会把引用内容分成独立文档，而非丢弃文字；可能使条件脱离对应问答。
3. **避免使用代码围栏存放规则**。`withIncludeCodeBlock(false)` 同样把代码块分为独立文档。问答正文优先使用普通文本。
4. **每块自包含**：块内必须重复商品型号或政策主题，不写「同上」「见上条」，也不依赖标题——标题会进 `metadata.title`，正文才是被向量化和被模型看到的内容。
5. **单块控制在 350 字以内**。监听器在解析后还会过一遍 `TokenTextSplitter`（默认 800 token），块过大时规则条件可能被切到下一个块里。
6. **条件与例外写在同一块**。「拆封能不能退」这类问题必须把适用条件、例外情形、运费承担一次写完，否则模型只能看到半条规则。

## 4. 入库方式

### 4.1 前置条件

```bash
# 独立演示库（不碰原 robot 库）
psql -U postgres -c "CREATE DATABASE milan_ecommerce;"
psql -U postgres -d milan_ecommerce -f sql/schema.sql
```

`application-dev.yml` 的 `datasource.url` 已指向 `milan_ecommerce`；`application-secret.yml`（本地、已 gitignore）提供 `api-key` 与 `base-url`，向量化模型为 `qwen3.7-text-embedding-flash`（1024 维）。

### 4.2 走现有上传流程

页面上传：进入「智能客服」页面 → 右上角设置 → 上传 `.md` 文件。
或直接调用接口（multipart 字段名固定为 `file`）：

```bash
for f in test-data/ecommerce/0[1-9]-*.md test-data/ecommerce/10-*.md; do
  curl -X POST -F "file=@$f" \
    http://localhost:8080/customer-service/md/upload
done
```

上传接口立即返回记录 id，向量化由 `AiCustomerServiceMdUploadedEvent` 异步完成：状态依次为 `0 待处理 → 1 向量化中 → 2 已完成`（失败为 `3`）。向量 ID 由「文件记录 ID + 正文」共同生成：同一记录后台重试保持幂等，不同上传记录拥有独立向量。重复上传会新建文件记录，替换文档时需显式删除旧记录，避免旧版本继续参与检索。文件归属行在向量化事务内加锁，强制删除会等待正在执行的事务结束；已被删除的记录不会继续写入向量。空白文件或扫描 PDF 没有可提取文字时标为失败，扫描件需先进行 OCR。

2026-10-21 的归属隔离修复只作用于新处理的文件；已有向量不会自动改写。若旧版本曾因重复正文发生归属覆盖，需要逐个删除受影响记录后重新上传各自源文档；本地备份保留供恢复。

若原有 01–05 文件已导入，只补充上传新资料，可运行：

```bash
for f in test-data/ecommerce/0[6-9]-*.md test-data/ecommerce/10-*.md; do
  curl -X POST -F "file=@$f" \
    http://localhost:8080/customer-service/md/upload
done
```

### 4.3 入库校验（实际执行过）

```sql
-- 文件处理状态：应为 2（已完成）10 条
SELECT id, original_file_name, file_size, status FROM t_ai_customer_service_md_storage ORDER BY id;

-- 按文件统计知识块与向量：每块都应有非空 embedding
SELECT metadata->>'originalFileName' AS file, count(*) AS chunks, count(embedding) AS with_vec,
       min(length(content)) AS min_len, max(length(content)) AS max_len
FROM t_vector_store GROUP BY 1 ORDER BY 1;

-- 文件关联元数据是否完整
SELECT metadata->>'mdStorageId' AS id, metadata->>'title' AS title
FROM t_vector_store LIMIT 5;
```

## 6. 2026-11-15 混合检索评测

- **题集**：eval/eval_questions.json 共 60 题，涵盖知识问答、条件与品类区分、口语化/同义问法、知识缺失、超范围和未接入的实时/操作能力。
- **数据版本**：默认知识库 ID 1「米兰数码商城」；10 份 Markdown、90 个自编 FAQ 知识块，PostgreSQL/pgvector 内 100 个非空向量；Elasticsearch 内 100 个同步文档。
- **混合模式**：生成模型 qwen3.8-flash、温度 0；Embedding qwen3.7-text-embedding-flash（1024 维）；pgvector Top 10 + Elasticsearch BM25 Top 10，经 RRF（k=60）融合 10 条，由 qwen3-rerank 重排后向模型提供 Top 3。
- **向量对照**：相同生成模型、温度、Embedding、题目和知识库；仅使用 pgvector Top 3，不启用 BM25、RRF 或 Rerank。运行配置、每题候选全文、最终 Top 3 与 SSE 回答均保存在两份原始 JSON。
- **逐题复核结果**：

| 模式 | 非空回答 | 完全正确 | 部分正确 | 错误/无回答 | 最终 Top-3 相关证据 | 候选相关证据 | 平均/中位耗时 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Hybrid + Rerank | 60/60 | 52/60（86.7%） | 8/60（13.3%） | 0/60 | 54/55（98.2%） | 55/55 | 5.68 / 4.86 秒 |
| Vector baseline | 60/60 | 53/60（88.3%） | 7/60（11.7%） | 0/60 | 55/55（100%） | 55/55 | 5.35 / 5.11 秒 |

- 检索统计中 55 道适用题包括可以由静态资料回答的政策/联系信息；D02、D03、D04、E17 虽然请求执行的业务操作未接入，但它们同时询问的退款流程、改地址政策、人工联系方式仍有知识库证据，因此纳入。C02、C03、D01、E16、E18 共 5 题不适用检索命中率：政策缺失/超范围、指定订单的实时物流、礼品包装政策缺失、实时库存与当天发货。所有 60 题仍分别评估回答安全性与完整性。
- Hybrid 在本题集上的完全正确数比纯向量少 1 题，最终 Top-3 相关证据也少 1 题；这轮结果**不支持宣称混合检索或 Rerank 提升了准确率**。两种模式各运行一轮，耗时仅是本机演示观察值，不是稳定延迟结论。
- 两轮各 60 题均有回答、未触发重试且每题均保存到证据；执行脚本只会在无回答且遇到已识别的传输异常时重试，不重采样成功回答。详见 [前半程逐题复核](eval/grading_hybrid_1_30.md)、[后半程逐题复核](eval/grading_hybrid_31_60.md)、[混合模式原始结果](eval/results_60_qwen3.8-flash_hybrid_20261115.json)、[向量对照原始结果](eval/results_60_qwen3.8-flash_vector-baseline_20261115.json)。
- 2026-10-20 的 DeepSeek 60 题与原 42 题结果保留在本报告后半部分，仅作历史记录；它们与本轮模型、检索链路或知识库版本不同，不能直接用来推算模型/检索改进效果。

## 7. 当前限制

1. **客服是单轮的**。`/customer-service/chat/completion` 不使用 `chatId` 维护历史，也没有客服消息持久化；多轮记忆和消息落库只在通用聊天 `/chat/**`。
2. **没有接入实际商城业务系统**。不能查询真实订单、物流、库存、支付/退款状态，也不能执行退款、取消订单、改地址、建工单或转人工。静态知识库可解释政策与联系方式，提示词也要求说明操作边界，但不等同业务接口或程序化权限检查。
3. **检索链路现为混合检索**：pgvector 向量 Top 10 与 Elasticsearch BM25 Top 10 经 RRF 融合，再由 qwen3-rerank 重排取 Top 3。当前未实现查询改写或相似度阈值校验；评测中 Hybrid + Rerank 没有优于纯向量基线。
4. **提示词不是确定性校验**。它降低越界回答概率，但不能保证模型每次都说全所有政策条件或拒绝无关推断；60 题中仍有 8 个回答被评为部分正确。
5. **业务规则没有程序化校验**。7 天期限、包邮门槛、保修时长等都以知识文本提供，模型可能漏讲例外。
6. **视频只覆盖分片传输/合并验证**。当前无视频转录或解析器；上传 .mp4、.mov、.avi 后无法建立可检索知识，记录会失败，不应视为已入库。
7. **数据与运行均为本地演示**。商城条款是虚构数据；本次 60 题每种模式只有一次运行，不能代表线上质量或 SLA。Docker Desktop 在开发期间曾间歇退出；本次两轮评测没有模型传输重试。
