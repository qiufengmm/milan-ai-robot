# 简历描述：米兰电商智能客服系统

**项目名称：** 米兰电商智能客服系统

**岗位：** 后端开发

**项目时间：** 2026.06 – 2026.09

**技术栈：** Java 21、Spring Boot 4.1.0、Spring AI 2.0.1、MyBatis-Plus 3.5.16、PostgreSQL/pgvector、Elasticsearch 9.4.2/IK、RAG、SSE、OkHttp、Docker

**项目简介：** 基于 Spring AI 与 RAG 构建的电商商品咨询及售后问答系统。复用现有文档上传、向量化和流式对话链路，针对虚构商城的商品参数、配送、发票、退换货与保修知识提供客服问答。

**主要工作：**

- 在现有单体框架上实现带 MD5/分片校验的文件上传与多知识库隔离；将知识库归属贯穿 PostgreSQL 向量与 Elasticsearch 索引，并通过可重试索引任务同步增量变更。
- 构建 pgvector 向量召回与 Elasticsearch BM25 关键词召回链路，使用 RRF 融合候选并调用 qwen3-rerank 重排，按知识库范围过滤后将 Top 3 证据送入客服 SSE 对话；保留原有前端对话流程并增加知识库选择与索引状态。
- 整理 10 份虚构商城文档（90 个 FAQ 知识块、100 个向量与 100 个 ES 文档），建立 60 题固定评测集。qwen3.8-flash、温度 0 的逐题复核结果：Hybrid + Rerank 52/60 完全正确、8 题部分正确；同模型纯向量对照为 53/60 完全正确、7 题部分正确。适用检索题的 Top 3 相关证据分别为 54/55 与 55/55，候选证据均为 55/55；本轮结果不支持宣称混合检索提升准确率。
- 本机单轮实测 Hybrid 平均 5.68 秒、中位数 4.86 秒；纯向量对照平均 5.35 秒、中位数 5.11 秒。两种模式各运行一次，不作为延迟 SLA 或稳定性结论。

**项目边界：** 商品、价格与店铺政策是虚构演示数据。客服未接入订单、物流、库存或售后业务接口，不执行退款、取消或改地址；客服链路没有多轮记忆或消息持久化。评测只代表固定演示题集和当前数据版本；8 题仍有遗漏或指引不完整，Hybrid + Rerank 也未优于纯向量对照。不得据此宣称线上准确率、准确率提升或稳定延迟。
