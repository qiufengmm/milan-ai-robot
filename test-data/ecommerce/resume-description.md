# 简历描述：米兰电商智能客服系统

**项目名称：** 米兰电商智能客服系统

**岗位：** 后端开发

**项目时间：** 2026.06 – 2026.09

**技术栈：** Java 21、Spring Boot 4.1.0、Spring AI 2.0.1、MyBatis-Plus 3.5.16、PostgreSQL、pgvector、SSE、Docker

**项目简介：** 基于 Spring AI 与 RAG 构建的电商商品咨询及售后问答系统。复用现有文档上传、向量化和流式对话链路，针对虚构商城的商品参数、配送、发票、退换货与保修知识提供客服问答。

**主要工作：**

- 复用现有 Markdown 知识库上传与异步处理流程，将 10 份电商客服文档解析、切分并向量化后写入 PostgreSQL/pgvector；构建覆盖 4 类商品和电商服务规则、90 个问答条目的演示知识库，最终入库 100 个知识块且均有非空向量。
- 调整客服 RAG 提示词，按商品资料和服务规则回答，遇到型号条件不明、知识缺失或实时订单问题时要求补充信息或说明能力边界；保留原有 SSE 流式接口和前端交互。
- 建立 60 题客服场景评测集，覆盖商品问答、口语化与歧义提问、规则例外、知识缺失和未接入能力；在 deepseek-v4-flash-0731、温度 0、topK=3 条件下人工复核，52 题完全正确（86.7%），8 题部分正确，60 题均取得回答；51 道适用题的 top-3 检索预览均含相关线索。
- 记录本地演示环境的实际响应耗时：中位数 9.93 秒、平均 13.2 秒（包含 4 题的 6 次额外请求，受 TLS 握手波动影响，不作为线上 SLA）。

**项目边界：** 商品、价格与店铺政策是虚构演示数据。当前客服未接入订单、物流和售后业务接口，不执行退款或地址修改；客服链路没有多轮记忆或消息持久化。60 题指标仅代表固定演示题集，8 题仍存在遗漏、过度追问或不当指引；检索相关性仅根据片段预览人工判断。原 42 题与旧模型结果均作为历史记录，不能据此宣称线上准确率或准确率提升。
