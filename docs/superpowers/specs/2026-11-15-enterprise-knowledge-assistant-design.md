# 米兰企业知识库智能问答平台改造方案（范围收敛版）

日期：2026-11-15  
原始方案状态（2026-11-15 编写）：当时仅完成审查和计划修订。后续业务实施与企业唯一流程清理已完成；本文保留设计历史，当前实现以[实施计划](../plans/2026-11-15-enterprise-knowledge-assistant.md)及[旧代码清理方案](../plans/2026-11-15-enterprise-only-cleanup.md)为准。本文替代此前较大的第一版方案。

## 1. 本期唯一目标

在现有 Java / Spring AI 项目上跑通一家企业内部的使用流程：

管理员创建账号和分配知识库权限 → HR / IT 上传并发布资料 → 员工提问、追问、查看依据 → 员工反馈错误 → 对应维护者修正文档并处理反馈。

项目用于简历和受控演示。默认只有「员工制度」「IT 支持」两个知识库，管理员可复用现有能力创建其他库。继续使用现有单体、单实例架构和现有模型配置。

本期以这条流程及必要的访问边界为完成标准。功能未在本文“保留范围”和验收流程中出现时，不自动加入实施任务；发现范围外建议先记录，由用户另行决定。

## 2. 使用人员与权限

| 人员 | 可以做什么 | 数据边界 |
| --- | --- | --- |
| 普通员工 | 选择授权库、提问和追问、查看参考片段、查看自己的历史、反馈错误 | 只读授权库；只访问本人会话 |
| HR / 行政维护者 | 普通员工功能，另可维护制度资料、发布替换版本、处理制度反馈 | 仅管理拥有 EDITOR 权限的库 |
| IT 维护者 | 普通员工功能，另可维护 IT 资料、发布替换版本、处理 IT 反馈 | 仅管理拥有 EDITOR 权限的库 |
| 系统管理员 | 创建和停用普通账号、创建知识库、配置库成员读写权限 | 全局管理账号和库；不提供浏览所有员工聊天的入口 |

实现只需要 ADMIN / USER 两种全局身份，以及知识库成员的 READER / EDITOR 两种权限。HR 和 IT 是演示岗位名称，不另建部门树或岗位权限系统；EDITOR 包含读取权限。管理员可维护库资料，但日常资料由业务维护者负责。

演示账号建议为 admin、hr_editor、it_editor、employee、restricted_employee。普通员工读两库，受限账号只读员工制度，供权限演示；密码从本地私有配置提供。

## 3. 需要跑通的人员流程

### 3.1 系统管理员

1. 使用预先初始化的管理员账号登录。
2. 创建 HR、IT 和员工账号，按知识库分配 READER / EDITOR。
3. 用户登录后只见可访问的库；维护者只见授权库的管理操作。
4. 停用普通账号或撤销库权限后，后续请求不能继续访问。

首个管理员由显式启用的本地初始化器在空用户表创建；不提供公开注册，不提交固定密码。管理员页面仅提供普通账号创建 / 启停、知识库创建和成员授权，不扩展成完整组织管理后台。

### 3.2 HR / IT 维护者

1. 登录，进入自己负责知识库的管理界面。
2. 上传文档，沿用现有分片、续传、解析、向量化、ES 同步流程。
3. 查看文件处理状态和解析出的代表片段；确认内容后发布。
4. 规则或排障步骤变化时，对同一逻辑文档上传新文件，检查就绪后点击“替换发布”。
5. 查看本库员工反馈，核对对应问题、回答和来源，必要时更新文档，再标记反馈已处理。

维护者通过有归属的反馈记录读取该次主动提交的问题、回答和来源快照，不放宽员工专用的“本人会话/来源”接口；不能提交任意answerId读取没有反馈关联的其他聊天。

资料上传后为草稿。处理成功与发布成功是两个状态；草稿不得进入员工问答。只提供当前版、历史版和撤回，不做版本比较、历史回滚或未来定时发布。

### 3.3 普通员工

1. 登录，选择可读知识库，新建会话。
2. 提问，如“出差报销要准备哪些材料？”
3. 程序检索当前已发布资料，流式回答，并展示实际参考文档和片段。
4. 点击来源查看依据，继续问“那最晚什么时候提交？”
5. 程序理解当前会话的追问，重新检索后回答；刷新后可看本人历史。
6. 认为有误时，在这条回答下点击“反馈问题”并填写原因。

切换知识库新建会话，避免旧库上下文混入新库。实际请假、报销、账号申请仍通过资料写明的 OA / IT 入口办理，程序不执行这些操作。

## 5. 技术与数据方案

保留 Java 21、Spring Boot 4.1.0、Spring AI 2.0.1、MyBatis-Plus、Vue 3、PostgreSQL / pgvector、Elasticsearch / IK。回答 / 必要的追问理解沿用 qwen3.8-flash；Embedding 沿用 qwen3.7-text-embedding-flash（1024 维）；重排沿用 qwen3-rerank。本轮未重新调用模型检测。

新建 milan_enterprise 数据库，使用独立 ES 索引 milan_enterprise_chunks_v1 和 data/enterprise/ 下的文件目录；复用现有 PG / ES 服务。旧库、旧文件、旧评测不导入员工账号。

只为新企业库提供初始化脚本，重复执行不得重置密码、授权或发布指针。本期不编写旧电商库通用升级器，不向旧库执行数据迁移。已有文件、分片、向量、outbox、会话、消息表继续使用原物理名称。

新增四张表：
- t_user：账号、密码哈希、显示名、ADMIN / USER、启用状态。
- t_knowledge_base_member：用户、知识库、READER / EDITOR。
- t_knowledge_document：逻辑文档、所属库、标题、当前发布的文件 ID。
- t_answer_feedback：回答消息 ID、反馈人、说明、OPEN / RESOLVED、处理人和处理说明。

扩展现有表：
- t_chat 增加 user_id、knowledge_base_id，新会话必须有归属。
- t_chat_message 增加 request_id、status、retrieval_query、sources_json、error_code；直接复用消息记录表达生成状态，不再新增 t_chat_turn。
- 文件表增加 document_id、version_no、uploaded_by、publish_status。
- 复用文件处理状态和 outbox 状态，不再建设另一套索引任务系统。

同一会话、同一 request_id、同一消息角色唯一；同一会话只允许一条 GENERATING 助手消息。重复提交返回 409 并提示查看历史，不做流结果重放。旧的 reasoning_content 字段保留兼容，新流程不展示或记录推理全文。

## 6. 最小必要的权限与安全边界

使用 Spring Security + HttpSession + BCrypt；浏览器走同源 /api 代理，保留 CSRF，Axios 和 SSE 都使用同一登录状态和 CSRF 头。登录 / 退出后刷新 Token；Cookie 为 HttpOnly，HTTPS 环境启用 Secure。

每次请求检查账号是否启用，知识库操作检查成员权限，会话操作检查本人归属。管理员全局库管理权限不绕过会话本人校验。权限判断先于查询改写、向量化、Rerank 和生成调用。

资料列表和处理片段：员工只能看当前已发布资料；EDITOR 可看本库草稿和历史版本。上传 / 发布 / 撤回 / 文件删除 / 重建索引 / 处理反馈必须有 EDITOR 或管理员权限。

保留已有上传大小、MD5、路径和累计分片校验；问题输入上限 4000 字符，历史最多最近 6 个已完成问答，历史文本最多 12000 字符，回答输出上限先配置为 1024 Token。用户停止后释放本次运行状态。此处不引入按 IP / 账号分桶的限流服务。

修复新页面使用到的 Markdown 原始 HTML 和动态代码块插值风险；普通日志不打印回答、参考资料、推理或密钥全文。引用接口不暴露本地文件路径。不承诺生成过程中实时撤权；后续请求和来源访问重新校验权限。

## 7. 文档发布与检索

首次上传建立逻辑文档和草稿 v1。上传替换版时必须选中同库逻辑文档，后端核对归属，并在文档锁内分配版本号。相同 MD5 复用已存在文件，不隐式创建版本或改变发布状态。

发布前要求解析 / 向量化完成且 ES 同步完成。锁住逻辑文档，在同一事务中归档旧版、发布新版并切换当前文件指针。新版本未就绪或发布失败时继续使用旧版。撤回当前版后，该文档不再进入新的问答检索。

在演示数据规模下，从数据库获得该库当前已发布文件 ID 集合，传给 PGVector 和 ES 两路过滤；空集合直接返回无资料。召回后再次检查文件状态和当前版。不得只召回后再剔除草稿，以免草稿挤占 TopK。

不做大规模索引授权方案。保留现有 outbox 重试即可；删除与旧索引未同步期间仍以数据库当前状态决定可见性。日常资料停用使用撤回；当前版和已引用历史版保留，草稿删除复用现有明确文件归属校验。

现有强制删除参数也必须服从上述边界，不能借旧文件接口删除当前版或已引用历史版。

维护者查看处理片段可复用按 fileId 查询 PG 中已解析内容的能力，仅返回本库授权内容，单次最多 3 个片段；不新增通用文件预览框架。

## 8. 追问、历史与流式回答

只迁移通用模块里必要的历史查询、排序、消息保存能力，增加用户和库归属检查。历史仅取助手已经 COMPLETED 的问答对，GENERATING / FAILED / CANCELLED 不作为追问依据。

首轮直接检索；有历史时以最近对话理解指代与用户条件，生成独立检索问题。追问理解只用同一个现有模型，不扩展为 Agent 或通用查询优化平台；明确原句可直接使用，无法确定的含糊追问应澄清。

每轮重新检索当前已发布资料。旧助手答案只帮助理解对话，不作为现行制度依据，不直接拼入最终回答的事实材料。

一次提问先保存用户消息和 GENERATING 助手记录。完成、失败、取消均更新同一助手记录；部分内容按真实状态保留。后端重启后把本实例遗留的 GENERATING 标为 FAILED，避免永久占用会话。不得因重连自动重复调用模型，前端关闭自动无限重试。

保留 SSE，最小事件为 meta、sources、delta、done、error。meta 返回 requestId 和 answerId；sources 为服务器实际选中的资料；delta 是正文；只有成功保存完整回答后发送 done，错误发送脱敏 error。

资料卡展示文档名、版本、片段；已有可靠页码 / 标题可附带，没有时不显示。卡片由后端检索结果生成，模型虚构的名称或 URL 不成为可点击来源。本期不做逐句引用校验器，也不以来源列表存在代替答案正确。

来源快照直接保存到助手消息 sources_json，员工打开来源时检查回答归属和当前库权限。历史卡片可保留当时版本；撤回或被替换资料标注历史版本，新提问不再使用它们。历史资料保留用于本人回看，不变为维护者浏览员工全部聊天的入口。

## 9. 页面和接口改造原则

复用现有 /customer-service/knowledge-bases、/customer-service/file/**、/customer-service/chat/completion，以及 /chat/new、/chat/list、/chat/message/list、/chat/summary/rename、/chat/delete。

新问答仍走客服 completion 地址，但库 ID 从已校验会话读取；请求包含 chatId、requestId、message，不接受客户端指定用户、角色、任意模型或可见文件清单。

只增加登录 / 当前用户、普通账号管理、库成员授权、发布 / 撤回、维护片段、回答来源、反馈等必要接口。原 /chat/completion 的自由生成入口在企业配置启用时停用，迁移完成前不向新员工开放旧历史旁路。

页面复用 CustomerServiceChatPage、Sidebar、ChatInputBox、KnowledgeBaseSelector、MarkdownFileDrawer：
- 问答页展示当前库、自己的历史、停止生成、资料卡和反馈。
- 管理抽屉增加文件版本 / 发布状态、片段查看与反馈两个简单页签。
- 新增登录页及一个账号 / 库授权页面。
- 管理员库创建复用现有表单；不新增管理员仪表盘、独立反馈门户或通用文件中心。
- 首页和旧商城入口重定向到统一问答页面，不为内部命名重构整套 API。

## 10. 演示数据和验收

首批 12 份虚构文档：制度 6 份（入职考勤、请假、报销、差旅、设备办公、服务目录），IT 6 份（账号登录、VPN、Wi-Fi、邮箱、软件安装、设备打印排障）。每份写明适用对象、规则、例外和虚构服务入口。增加一份报销 v2 验证替换发布，不要求凑知识块数。

流程先用 6 个代表性用例验证，然后正式评测 60 个用例：制度单轮 20、IT 单轮 15、多轮 8、条件澄清 5、无依据 / 注入 5、权限 4、版本替换 3。多轮用例含多次请求，报告分别列用例数和请求数。

记录检索证据是否命中、回答事实 / 条件是否正确、参考片段是否支持答案，以及权限、追问、版本场景是否通过；耗时和每次失败 / 重试另记。指标用实测值，不设必须达到某个百分比才算“做完流程”的目标，不反复重采样刷分。

权限用例验证拒绝发生在模型调用前。失败说明区分认证、检索、模型、TLS、取消和流不完整；仅确认 TLS 握手失败且无输出时允许评测脚本显式重试一次，原失败保留。只跑默认混合检索链路，不自动增加消融或压测。

必须通过的端到端验收：
1. 管理员创建人员并分配读写权限。
2. HR 发布制度，员工能提问、追问、看来源和本人历史。
3. IT 发布排障资料，员工切库后可咨询。
4. 普通员工不能上传 / 发布；HR 不能修改 IT 库；不同员工看不到彼此会话。
5. 员工反馈错误，负责该库的维护者查看、修正文档、标记已处理。
6. v2 未发布时仍回答 v1，发布后新问题使用 v2，撤回后不继续检索该文档。
7. 生成失败、停止、刷新、重复提交不会伪装成功或串会话。

评测结果有错误时如实列明，修复阻塞上述流程的缺陷；不为追求未经约定的指标扩展功能。

## 11. 旧功能和交付边界

先迁移记忆、消息、历史，再停用独立自由聊天和 SearXNG / 网页抓取。输入框解除旧模型 Store 引用后再停用旧选择逻辑。OkHttp、RAG 和事件线程池、分片上传和 outbox 继续保留。

过渡阶段仍有旧控制器对搜索Bean的注入依赖，企业配置需要保留装配所需的静态属性，不能先删属性造成启动失败；旧生成入口关闭且不调用搜索服务。完成会话迁移后，再一并解除旧注入、停用搜索Bean并清理配置，不要求搜索容器在线。

旧电商数据、60 题历史结果、联网 Token / 耗时基准保留作历史，不写成新版本成果。多文件清理由用户按明确路径手动处理，严格遵守禁止批量删除文件或目录的约束。

本期交付仅为上述人员流程对应的代码、企业库初始化、12 份资料和1份替换版、60 用例实测报告、README、演示步骤与四条有实现依据的简历描述。类名 / 表名仍带原项目历史名称不影响验收。

本轮只修订方案与计划；不写业务代码，不运行测试、建库、导入、模型调用、提交或推送。
